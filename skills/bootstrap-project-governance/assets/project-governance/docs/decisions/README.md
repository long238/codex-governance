# Decision 索引

Decision 解释已经接受、具有长期影响且未来容易误改或重复争论的设计选择。它不代替当前代码、测试和架构事实文档，也不赋予 Agent 额外决策权限。

## 准入条件

适合记录：

- 模块或层级职责与依赖方向；
- 状态所有权、线程或异步模型；
- 公共接口、持久化或关键兼容策略；
- 核心依赖、技术路线和重要事实唯一来源；
- 用户明确否决且很可能再次被提出的长期替代方案。

普通实现细节、小范围界面调整、一次性修复、普通重命名、未批准候选方案不创建 Decision。

默认只记录当前任务新触发的长期决定，不主动扫描历史文档或聊天批量补录。历史提取与补录仅在用户明确要求时进行，并核对决定是否已接受、是否被替代；无法确认的内容不能写成已接受决定。记录当前任务内已批准的决定本身不需要重复审批。

## 文件约定

- 建议命名：`DEC-YYYYMMDD-short-title.md`。
- 建议状态：`Accepted`、`Superseded`。
- 每份内容至少包含背景、决定、理由、后果、替代方案和验证或迁移影响。
- 被替代的 Decision 保留历史并指向新条目，不静默改写旧决定。
