# 项目文档导航

> 状态：当前文档入口；只负责事实来源与阅读路由，不定义新的业务规则。

## 文档职责

- 当前磁盘代码、构建清单、自动化测试和实际执行结果说明“当前已经实现什么”。
- 根 `AGENTS.md` 定义开发过程、审批门槛、禁止事项和验证最低要求。
- 当前事实文档记录已实现架构、行为契约和已知例外。
- Plan、Decision 与 Playbook 分别记录活动实施方案、已接受长期选择和已验证排障路径，不能替代当前实现证据。

代码与规范不一致时，按根 `AGENTS.md` 区分普通冲突和已批准任务的迁移中间状态。涉及高风险范围时，不得在整理文档时自行决定修代码还是修文档。

## 最小读取流程

1. 根据功能或问题选择一个主章节，按标题、关键词和受影响路径定位，不得无差别加载整个 `docs/`。
2. 按下文“专项阅读与影响判断”检查直接和间接影响，只有命中相应条件时才追加相关章节。
3. 普通相对链接只表示事实归属或延伸阅读，不触发递归全文读取；强制附加阅读的详细条件统一在本入口维护。
4. 恢复已知活动任务时，先读匹配 WORKLOG 的检查点、验证证据和 Next，按根 `AGENTS.md` 做最小工作树检查，不重新执行任务启动路由。
5. 当前实现争议回到代码、构建清单、自动化测试和实际执行结果核对。
6. 路由缺项时先按关键词定位现有文档，不扩大为全量扫描；在获准的文档维护范围内补齐入口，只读任务只报告缺项。

## 按功能查找

| 功能或问题 | 唯一主要行为说明 |
|---|---|
| 项目具体功能、流程及异常结果：待确认 | 从目标项目现有文档核对后，逐项链接到实际主章节 |

应用时按目标项目实际功能填写本表，不预设业务名称，不为凑齐分类创建空文档。小项目可将多个相关功能放在同一文档的不同章节。

## 专项阅读与影响判断

| 实际影响范围 | 追加阅读与核对 |
|---|---|
| 模块边界、依赖方向、状态所有权或并发模型 | [当前架构](architecture.md#当前实现)及受影响约束 |
| 配置字段、默认值、保存、读取、生效或清理时机 | 项目配置事实的唯一出处：待确认；涉及交付输入时同时核对其安装、发布及升级约定 |
| 日志、事件、请求与终态、关联信息或诊断字段 | 按下文“日志影响判断”核对项目已有规范、调用点与测试；具体文档及组合：待确认 |
| 依赖、运行时资源、安装或交付变化 | 项目依赖及交付事实的唯一出处：待确认；同时核对依赖声明、实际产物和许可证要求 |
| 构建、测试、运行验证或交付验收 | [测试与验证](testing.md#已确认入口)，仅按被验证行为追加相关领域章节 |

配置、日志、依赖和交付规则可以位于现有文档中；应用时将“待确认”替换为已核对的章节链接及必要的同时阅读组合。没有证据时保留待确认和核对位置，不虚构文件或强制拆分目录。

### 日志影响判断

业务流程变更时，判断是否直接或间接影响事件、请求与终态、关联标识、请求时的参与者或配置快照、字段与秘密清洗、级别或频率。命中任一项或无法确认无影响时，核对项目已有日志规范相关章节、调用点和测试；不得仅因没有修改日志调用就认定无影响。确认无日志影响的纯布局、样式等修改不额外追加阅读。

具体事件分类、字段、脱敏、保留及上传策略必须从目标项目核对；缺失时报告待确认，不从其他项目带入策略。

## 辅助材料

| 材料 | 读取时机 |
|---|---|
| [Plans 生命周期](plans/README.md) | 仅在任务明确关联活动 Plan 时读取具体文件 |

`.codex/worklogs/` 是本地执行恢复现场，不属于项目事实路由。只有继续某个已知活动任务时才读取对应 task slug 文件，不得扫描全部 WORKLOG。

## 文档状态

- `architecture.md` 描述当前已确认架构，并将未来建议放在独立章节。
- `testing.md` 保存从项目中实际核对的命令、测试范围和环境边界。
- `plans/` 只保存活动 Plan；Plan 不是当前系统事实。
- `decisions/` 解释已接受长期选择的原因和后果，不代替当前架构文档。
- `playbook/` 只保存根因和修复均已验证的可复用排障路径。
- 项目是否存在其他当前事实文档：待确认。

## 维护规则

1. 一项详细事实只保留一个规范出处，其他文档使用简短摘要和相对链接。
2. 过程门槛放在根 `AGENTS.md`；具体命令放在 `testing.md`；当前架构事实放在 `architecture.md`。
3. 更新功能时优先归入已有主章节，同时处理入口、旧名称和重复描述，不能仅在文末追加或新建近似文档。
4. 每份当前文档只保留一个一级标题，标题应覆盖其下内容；长文提供章节导航，避免在表格单元格中堆放完整流程。
5. 可从构建、测试或发布配置取得的完整清单，以对应可执行来源为准；文档解释用途、归属和验证边界，不手工复制另一份声称始终完整的清单。
6. 新增文档时明确其属于当前事实、Proposal、活动 Plan、Decision 或 Playbook，不得混用定位；当前行为与未来建议使用独立章节或独立文档。
7. 新增、删除或重命名章节及文档后检查相对链接、标题锚点和本路由；强制阅读组合的详细条件只在本入口维护。
