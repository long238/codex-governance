# 项目文档导航

> 状态：当前文档入口；只负责事实来源与阅读路由，不定义新的业务规则。

## 文档职责

- 当前磁盘代码、构建清单、自动化测试和实际执行结果说明“当前已经实现什么”。
- 根 `AGENTS.md` 定义开发过程、审批门槛、禁止事项和验证最低要求。
- 当前事实文档记录已实现架构、行为契约和已知例外。
- Plan、Decision 与 Playbook 分别记录活动实施方案、已接受长期选择和已验证排障路径，不能替代当前实现证据。

代码与规范不一致时，必须报告差异。涉及高风险范围时，不得在整理文档时自行决定修代码还是修文档。

## 最小读取流程

1. 根据任务从下表选择一个主文档或主章节，不得无差别加载整个 `docs/`。
2. 只有任务实际影响其他领域时才追加对应文档。
3. 普通相对链接只表示事实归属或延伸阅读，不触发递归全文读取。
4. 当前实现争议回到代码、构建清单、自动化测试和实际执行结果核对。
5. 若当前表格没有覆盖项目已存在的领域文档，应先将其职责和读取条件补入本路由。

## 阅读路由

| 任务内容 | 主文档 | 追加条件 |
|---|---|---|
| 架构、模块边界、依赖方向、状态所有权或并发模型 | [当前架构](architecture.md) | 只按实际影响追加项目领域文档 |
| 构建、自动化测试、运行验证或交付验收 | [测试与验证](testing.md) | 只按被验证行为追加项目领域文档 |
| 活动实施方案 | [Plans 生命周期](plans/README.md) | 仅在任务明确关联活动 Plan 时读取具体文件 |
| 长期设计选择及其理由 | [Decision 索引](decisions/README.md) | 准备改变长期边界或用户要求回顾时先查索引 |
| 已验证的非显然故障排查 | [Playbook 索引](playbook/README.md) | 症状或模块匹配时按关键词查找具体条目 |
| 项目专属领域事实 | 待确认 | 从现有文档结构核对后补充本表 |

`.codex/worklogs/` 是本地执行恢复现场，不属于项目事实路由。只有继续某个已知活动任务时才读取对应 task slug 文件，不得扫描全部 WORKLOG。

## 文档状态

- `architecture.md` 描述当前已确认架构，并将未来建议放在独立章节。
- `testing.md` 保存从项目中实际核对的命令、测试范围和环境边界。
- `plans/` 只保存活动 Plan；Plan 不是当前系统事实。
- `decisions/` 解释已接受长期选择的原因和后果，不代替当前架构文档。
- `playbook/` 只保存根因和修复均已验证的可复用排障路径。
- 项目是否存在其他当前事实文档：待确认。

## 维护规则

1. 一项详细事实只保留一个规范出处，其他文档使用简短摘要和相对链接。
2. 过程门槛放在根 `AGENTS.md`；具体命令放在 `testing.md`；当前架构事实放在 `architecture.md`。
3. 新增文档时明确其属于当前事实、Proposal、活动 Plan、Decision 或 Playbook，不得混用定位。
4. 当前行为与未来建议必须使用独立章节或独立文档。
5. 新增、删除或重命名文档后检查相对链接并更新本路由。
