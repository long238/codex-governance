# Plans 生命周期

Plan 是高风险、多阶段或长期实施任务的执行工具，不是当前实现事实，也不是所有任务的必需文件。

## 何时创建

- 底层能力大改、框架或架构重构；
- 多阶段迁移或高风险长期任务；
- 需要跨会话维护稳定实施顺序；
- 用户明确要求形成可落地的阶段任务书。

普通局部任务和可在当前会话完成验证的修改，不应仅为形式创建 Plan。

## 状态

- `Draft`：候选方案，尚未批准实施。
- `Approved`：用户已批准，尚未开始或正在等待实施窗口。
- `In Progress`：正在按批准范围实施。
- `Blocked`：存在明确阻塞，不能在当前授权或环境下继续。
- `Completed` 与 `Cancelled`：关闭状态；关闭方式和是否保留详细文件由项目约定确认。

项目当前采用的关闭索引或归档方式：待确认。

## 最小内容

活动 Plan 应包含：

- 状态、目标和非目标；
- 已确认事实与待确认项；
- 实施阶段、影响范围和迁移顺序；
- 风险、回退或兼容策略；
- 每阶段验收条件和最终验证；
- 与相关 Decision、事实文档和 WORKLOG 的关系。

## 关闭

关闭前先把最终稳定事实同步到唯一当前事实文档。Plan 中的过程、假设和旧名称不得继续作为当前行为依据。若项目使用关闭索引，应只保留足够定位历史的摘要和版本控制引用。
