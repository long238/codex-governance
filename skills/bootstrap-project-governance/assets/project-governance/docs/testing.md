## 验证等级对应范围

- **V0**：链接或引用、失效旧引用、未清理标记、`git diff --check` 和最终 diff 审查。
- **V1**：项目已确认的最小构建或静态检查、目标功能冒烟、明显相邻影响检查。
- **V2**：相关构建、已有相关自动化测试、目标业务路径和相邻回归。
- **V3**：受影响目标完整构建、相关自动化测试、真实目标路径、关键异常与边界、模块回归和明确证据。

风险等级的定义和审批门槛以根 `AGENTS.md` 为准。本文件只维护本项目用于履行这些门槛的真实命令和环境边界。

## 真实性边界

- 编译、静态检查、单元测试、集成测试、人工冒烟、目标环境验证和发布包验证是不同证据，不得互相替代。
- 模拟或替身环境只能证明其覆盖的契约，不能证明真实外部环境行为。
- 命令没有实际执行时写“未执行”，不能根据代码阅读推断通过。
- 失败验证必须保留关键错误和影响判断；不得通过删测试、放宽断言或屏蔽错误制造通过。
- 测试框架报告的跳过必须单列原因和未覆盖范围；即使总命令成功退出，也不得将跳过项算作通过。
- 新增自动化守卫规则时，用已知违规样例证明守卫能够拒绝该违规，并验证正常输入仍可通过；文本扫描或有限样例不能证明全部架构约束。
- 配置变更的验证应覆盖实际读取和约定生效时机，以及受影响的保存、重启或清理行为；仅验证字段可保存不足以证明效果。

## 结果记录格式

最终报告至少分为：

- **已执行并通过**：命令或检查、配置、结果。
- **已执行但失败**：命令或检查、关键错误、是否阻断交付。
- **跳过**：测试框架报告的跳过项、原因和未覆盖范围。
- **未执行**：原因、剩余风险和后续应执行的验证。

若项目依赖真实设备、服务、账号、网络或特定主机能力，应在此记录哪些验证可自动完成、哪些只能在目标环境完成。
